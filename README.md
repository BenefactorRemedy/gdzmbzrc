# SC-PRIORITY-DEMO-LITE RU v2.2

Система распределения запасов по приоритетам с поддержкой различных стратегий allocation.

## Описание

SC-PRIORITY-DEMO-LITE - это Python-проект для управления распределением запасов между заказами с учетом:
- Приоритетов заказов (классы A, B, C)
- Резервов запасов
- Различных стратегий распределения (Partial vs All-or-nothing)
- Сортировки по датам выполнения
- Режима "Анти-ноль" для минимизации нулевых выделений

## Использование

### Интерактивный режим

```bash
python -m src.main --interactive
```

Или:

```bash
python -m src.main
```

Система запросит ввод данных для вопросов Q1-Q6:

- **Q1**: Список заказов (формат: `ID|SKU|QTY|CLASS|DUE_DATE`)
- **Q2**: Список запасов (формат: `SKU|QTY`)
- **Q3**: Partial allocation? (YES/NO)
- **Q4**: Зарезервированные количества (формат: `SKU|QTY` или `NO`)
- **Q5**: Sort by due date? (YES/NO)
- **Q6**: Service mode (Anti-zero)? (YES/NO)

### Режим командной строки

```bash
python -m src.main \
  --q1 "ORD001|SKU-A|100|A|15.01.2026
ORD002|SKU-B|50|B|-" \
  --q2 "SKU-A|150
SKU-B|80" \
  --q3 "YES" \
  --q4 "NO" \
  --q5 "NO" \
  --q6 "NO" \
  --output report.md
```

### Пример входных данных

**Q1: Заказы**
```
ORD001|SKU-A|100|A|15.01.2026
ORD002|SKU-A|50|B|-
ORD003|SKU-B|30|C|20.01.2026
```

**Q2: Запасы**
```
SKU-A|150
SKU-B|40
```

**Q3**: YES (разрешить частичное выделение)  
**Q4**: NO (нет резервов)  
**Q5**: NO (FIFO, не сортировать по дате)  
**Q6**: NO (режим Simplicity, без Anti-zero)

## Логика распределения

### Приоритеты (A → B → C)

Система распределяет запасы в порядке приоритета:
1. Сначала все заказы класса A
2. Затем все заказы класса B
3. В последнюю очередь заказы класса C

### Q3: Partial vs All-or-nothing

- **YES (Partial)**: Заказ может получить частичное выделение
- **NO (All-or-nothing)**: Заказ получает либо всё, либо ничего

### Q4: Резервы

Зарезервированные запасы вычитаются из доступного количества:
```
available = stock - reserved
```

### Q5: Сортировка

- **YES**: Заказы сортируются по `due_date` (раньше = выше приоритет)
- **NO**: FIFO (в порядке поступления)

### Q6: Service vs Simplicity

**Simplicity (NO)**: Обычное FIFO распределение

**Service (YES)**: "Анти-ноль" логика
- Если есть дефицит и несколько заказов конкурируют за один SKU
- Сначала каждый заказ получает по 1 шт (чтобы никто не получил 0)
- Остаток распределяется по FIFO

## Валидация

### STOP (критические ошибки)

- **C1**: Дубликаты ID заказов
- **C2**: Дубликаты SKU в запасах
- **C3**: QTY заказа ≤ 0
- **C4**: QTY запаса < 0

### WARN (предупреждения)

- **B1**: SKU заказа отсутствует в запасах
- **B2**: Зарезервировано больше чем доступно
- **B3**: Заказы класса C (низкий приоритет)

## Метрики

### Fill Rate
```
Fill Rate = (Σ allocated / Σ requested) × 100%
```

### Count Zero
Количество заказов с нулевым выделением.

### Risk Level
- **GREEN**: Fill Rate ≥ 95% и Count Zero = 0
- **YELLOW**: Fill Rate ≥ 80% или Count Zero ≤ 2
- **RED**: Fill Rate < 80% или Count Zero > 2

## Формат отчета

Система генерирует отчет в формате Markdown с тремя секциями:

1. **Статус системы** (OK/WARN/STOP)
2. **Входные данные** (сводка Q1-Q6)
3. **Результаты распределения** (таблица, метрики)

Пример:

```markdown
# ОТЧЕТ СИСТЕМЫ SC-PRIORITY-DEMO-LITE RU v2.2

## 1. СТАТУС СИСТЕМЫ
**СТАТУС:** ✅ OK

## 2. ВХОДНЫЕ ДАННЫЕ
| Вопрос | Ответ |
|--------|-------|
| Q1: Количество заказов | 3 |
| Q2: Количество SKU | 2 |
...

## 3. РЕЗУЛЬТАТЫ РАСПРЕДЕЛЕНИЯ
| ID заказа | SKU | Запрошено | Выделено | Fill Rate | Статус |
|-----------|-----|-----------|----------|-----------|--------|
| ORD001 | SKU-A | 100 | 100 | 100.0% | ✅ OK |
...

### Метрики
- **Fill Rate:** 95.00%
- **Count Zero:** 0
- **Risk Level:** 🟢 GREEN
```
