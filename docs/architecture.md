# Архитектура SC-PRIORITY-DEMO-LITE RU v2.2

## Обзор

SC-PRIORITY-DEMO-LITE RU v2.2 — это система распределения складских запасов с приоритетами, реализованная на Python. Система обеспечивает детерминированное распределение товаров по заказам с учетом приоритетов A → B → C.

## Компоненты системы

### 1. Модели данных (`src/models.py`)

**Основные классы:**
- `Order` — заказ с полями: ID, SKU, количество, класс приоритета, срок
- `Stock` — остаток товара с количеством и резервом
- `InputData` — входные данные Q1-Q6
- `AllocationResult` — результат распределения для заказа
- `ValidationError` — ошибка валидации (STOP/WARN)
- `AllocationReport` — полный отчет о распределении

### 2. Парсер (`src/parser.py`)

Преобразует текстовые входные данные в объекты:
- `parse_q1()` — парсинг заказов (формат: OrderID|SKU|Qty|Class|DueDate)
- `parse_q2()` — парсинг остатков (формат: SKU|Qty)
- `parse_q3()` — частичная отгрузка (YES/NO)
- `parse_q4()` — резервы (формат: SKU|Reserved)
- `parse_q5()` — сортировка по дате (YES/NO)
- `parse_q6()` — режим сервис/простота (YES/NO)

### 3. Валидатор (`src/validator.py`)

Проверяет входные данные на критические ошибки и предупреждения:

**STOP (критические):**
- C1: Дубликаты Order ID
- C2: Дубликаты SKU в остатках
- C3: Quantity <= 0 в заказах
- C4: Quantity < 0 в остатках

**WARN (предупреждения):**
- B1: SKU в заказах отсутствует в остатках
- B2: Резерв превышает остаток
- B3: Есть заказы класса C

### 4. Аллокатор (`src/allocator.py`)

Ядро распределения запасов:

**Основная логика:**
1. Сортировка заказов по приоритету A → B → C
2. Внутри приоритета: по дате (Q5) или FIFO
3. Распределение с учетом:
   - Available stock = Stock - Reserved
   - Q3: Partial vs All-or-nothing
   - Q6: Service (anti-zero) vs Simplicity

**Режим "Сервис" (Q6=YES):**
При дефиците и конкуренции:
1. Раздать по 1 единице каждому заказу
2. Остаток распределить по FIFO

### 5. Метрики (`src/metrics.py`)

Расчет показателей:
- **Fill Rate** — процент выполнения заказов
- **Zero Count** — количество заказов с нулевым распределением
- **Risk Level** — уровень риска:
  - GREEN: Fill Rate ≥ 90% И zero_count = 0
  - RED: Fill Rate < 70% ИЛИ zero_count > 30%
  - YELLOW: все остальные

### 6. Форматтер (`src/formatter.py`)

Генерация Markdown отчетов с секциями:
1. Статус (SUCCESS/WARN/STOP)
2. Ошибки и предупреждения
3. Входные данные (Q1-Q6)
4. Результаты распределения
5. Метрики

### 7. CLI (`src/main.py`)

Точка входа с двумя режимами:
- **Интерактивный** (`--interactive`) — ввод данных через консоль
- **Файловый** — параметры через аргументы командной строки

## Поток данных

```
Входные данные (Q1-Q6)
    ↓
Parser (текст → объекты)
    ↓
Validator (STOP/WARN проверки)
    ↓
Allocator (распределение запасов)
    ↓
Metrics (расчет показателей)
    ↓
Formatter (генерация отчета)
    ↓
Markdown отчет
```

## Алгоритм распределения

1. **Подготовка:**
   - Парсинг Q1-Q6
   - Валидация (STOP → прервать, WARN → продолжить)
   - Расчет available = stock - reserved

2. **Сортировка заказов:**
   - Первичная: по приоритету (A → B → C)
   - Вторичная: по дате (Q5=YES) или FIFO (Q5=NO)

3. **Распределение:**
   - Если Q6=YES (Service): применить анти-ноль логику
   - Для каждого заказа:
     - Если Q3=YES: выделить min(запрос, доступно)
     - Если Q3=NO: выделить все или ничего

4. **Метрики и отчет:**
   - Расчет Fill Rate, Zero Count, Risk Level
   - Генерация Markdown отчета

## Примеры использования

### CLI

```bash
# Интерактивный режим
python -m src.main --interactive

# Через параметры
python -m src.main --q1 "ORD001|SKU-A|100|A|-" --q2 "SKU-A|150" --q3 YES

# С выводом в файл
python -m src.main --q1 "..." --q2 "..." --output report.md
```

### Программный API

```python
from src.main import run_allocation

report = run_allocation(
    q1="ORD001|SKU-A|100|A|-",
    q2="SKU-A|150",
    q3="YES",
    q6="YES"  # Service mode
)

print(f"Status: {report.status}")
print(f"Fill Rate: {report.metrics['fill_rate']}%")
```
