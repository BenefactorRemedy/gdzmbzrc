# Правила SC-PRIORITY-DEMO-LITE RU v2.2

## Основные принципы

### Приоритеты A → B → C

Система использует строгую иерархию приоритетов:
1. **Класс A** — высший приоритет, обрабатывается первым
2. **Класс B** — средний приоритет, обрабатывается после A
3. **Класс C** — низкий приоритет, обрабатывается последним

Заказы с более высоким приоритетом **всегда** получают товар раньше.

### Доступные запасы

```
Available Stock = Stock Quantity - Reserved Quantity
```

Только доступные запасы могут быть распределены по заказам.

## Входные параметры (Q1-Q6)

### Q1: Заказы

Формат: `OrderID|SKU|Qty|Class|DueDate`

Пример:
```
ORD001|SKU-A|100|A|2026-02-15
ORD002|SKU-B|50|B|-
```

**Правила:**
- OrderID должен быть уникальным (иначе C1)
- Qty должно быть > 0 (иначе C3)
- Class: A, B или C
- DueDate в формате YYYY-MM-DD или "-"

### Q2: Остатки

Формат: `SKU|Qty`

Пример:
```
SKU-A|500
SKU-B|200
```

**Правила:**
- SKU должен быть уникальным (иначе C2)
- Qty должно быть >= 0 (иначе C4)

### Q3: Частичная отгрузка

- **YES** — разрешена частичная отгрузка
- **NO** — "все или ничего" (all-or-nothing)

**Примеры:**
- Q3=YES: заказ на 100 при наличии 60 → получит 60
- Q3=NO: заказ на 100 при наличии 60 → получит 0

### Q4: Резервы

Формат: `SKU|Reserved`

Пример:
```
SKU-A|50
```

**Правила:**
- Резерв уменьшает доступное количество
- Если резерв > остаток → предупреждение B2

### Q5: Сортировка по дате

- **YES** — сортировать по дате внутри каждого приоритета
- **NO** — FIFO (First In First Out)

**Примеры:**

Q5=YES:
```
Приоритет A:
  ORD001 (2026-03-01) 
  ORD002 (2026-02-15) ← обработается первым
  ORD003 (2026-02-20)
```

Q5=NO:
```
Приоритет A:
  ORD001 ← обработается первым (FIFO)
  ORD002
  ORD003
```

### Q6: Режим работы

- **YES** — режим "Сервис" (анти-ноль)
- **NO** — режим "Простота" (FIFO)

## Режим "Сервис" (Q6=YES)

**Цель:** Предотвратить нулевое распределение при дефиците и конкуренции.

**Алгоритм:**
1. Проверить дефицит: `available < total_demand`
2. Проверить конкуренцию: количество заказов > 1
3. Если оба условия выполнены:
   - Раздать по 1 единице каждому заказу
   - Остаток распределить по FIFO

**Пример:**
```
Заказы (приоритет A):
  ORD001: 100 шт
  ORD002: 80 шт
Остаток: 120 шт

Режим Сервис (Q6=YES):
  1. По 1 каждому: -2 шт → остаток 118
  2. FIFO:
     - ORD001: 1 + 99 = 100 (полный запрос)
     - ORD002: 1 + 19 = 20
  
Режим Простота (Q6=NO):
  - ORD001: 100 (полный запрос)
  - ORD002: 20
```

## Валидация

### STOP ошибки (критические)

Останавливают выполнение, распределение не производится.

| Код | Описание | Пример |
|-----|----------|--------|
| C1 | Дубликаты Order ID | ORD001 встречается дважды |
| C2 | Дубликаты SKU в остатках | SKU-A встречается дважды |
| C3 | Qty <= 0 в заказах | Заказ с qty = 0 или -5 |
| C4 | Qty < 0 в остатках | Остаток с qty = -10 |

### WARN предупреждения (не критические)

Не останавливают выполнение, но выводятся в отчете.

| Код | Описание | Пример |
|-----|----------|--------|
| B1 | SKU отсутствует в остатках | Заказ на SKU-X, но SKU-X нет в Q2 |
| B2 | Резерв > остаток | Остаток 100, резерв 150 |
| B3 | Есть заказы класса C | ORD005 имеет класс C |

## Метрики

### Fill Rate (процент выполнения)

```
Fill Rate = (Σ allocated / Σ requested) × 100%
```

**Примеры:**
- Запрошено 200, выделено 200 → 100%
- Запрошено 200, выделено 150 → 75%
- Запрошено 200, выделено 100 → 50%

### Zero Count (количество нулевых распределений)

Количество заказов, которые получили 0 единиц товара.

### Risk Level (уровень риска)

| Уровень | Условия |
|---------|---------|
| 🟢 GREEN | Fill Rate ≥ 90% **И** zero_count = 0 |
| 🔴 RED | Fill Rate < 70% **ИЛИ** zero_count > 30% от общего числа |
| 🟡 YELLOW | Все остальные случаи |

**Примеры:**

```
10 заказов, Fill Rate = 95%, Zero Count = 0 → GREEN
10 заказов, Fill Rate = 85%, Zero Count = 1 → YELLOW
10 заказов, Fill Rate = 65%, Zero Count = 2 → RED
10 заказов, Fill Rate = 80%, Zero Count = 4 → RED (40% > 30%)
```

## Статусы выполнения

| Статус | Описание |
|--------|----------|
| SUCCESS | Распределение выполнено успешно, нет ошибок и предупреждений |
| WARN | Распределение выполнено с предупреждениями (B1-B3) |
| STOP | Распределение остановлено из-за критических ошибок (C1-C4) |

## Приоритет выполнения

1. **Валидация** — сначала проверка всех STOP и WARN условий
2. **Сортировка** — по приоритету A→B→C, затем по дате или FIFO
3. **Анти-ноль** (если Q6=YES) — предварительное распределение по 1 шт
4. **Основное распределение** — выделение остатков по заказам
5. **Метрики** — расчет Fill Rate, Zero Count, Risk Level
6. **Отчет** — генерация Markdown отчета

## Примеры сценариев

### Сценарий 1: Нормальное распределение

```
Q1: ORD001|SKU-A|50|A|-
    ORD002|SKU-A|30|B|-
Q2: SKU-A|100
Q3: YES

Результат:
  ORD001 (A): 50 ← полный запрос
  ORD002 (B): 30 ← полный запрос
  Fill Rate: 100%
  Risk Level: GREEN
```

### Сценарий 2: Дефицит с приоритетами

```
Q1: ORD001|SKU-A|50|B|-
    ORD002|SKU-A|30|A|-
    ORD003|SKU-A|20|C|-
Q2: SKU-A|70
Q3: YES

Результат:
  ORD002 (A): 30 ← обработан первым
  ORD001 (B): 40 ← частичное выполнение
  ORD003 (C): 0 ← ничего не осталось
  Fill Rate: 70%
  Risk Level: YELLOW
```

### Сценарий 3: All-or-nothing

```
Q1: ORD001|SKU-A|100|A|-
    ORD002|SKU-A|80|A|-
Q2: SKU-A|120
Q3: NO ← все или ничего

Результат:
  ORD001 (A): 100 ← полный запрос (хватает)
  ORD002 (A): 0 ← недостаточно для полной отгрузки
  Fill Rate: 55.6%
  Risk Level: RED
```

### Сценарий 4: Service mode (анти-ноль)

```
Q1: ORD001|SKU-A|50|A|-
    ORD002|SKU-A|50|A|-
    ORD003|SKU-A|50|A|-
Q2: SKU-A|80
Q3: YES
Q6: YES ← режим сервис

Результат:
  Шаг 1: По 1 каждому (3 шт), остаток 77
  Шаг 2: FIFO
    ORD001: 1 + 49 = 50
    ORD002: 1 + 26 = 27
    ORD003: 1 + 0 = 1 ← не ноль!
  Fill Rate: 52%
  Zero Count: 0 ← анти-ноль работает
```
