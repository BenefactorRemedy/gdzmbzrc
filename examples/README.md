# 📚 Примеры тестовых сценариев

Эта директория содержит готовые примеры для демонстрации работы системы SC-PRIORITY-DEMO-LITE RU v2.2.

## 🚀 Как использовать примеры

### Вариант 1: Копирование команды
Скопируйте команду из файла примера и выполните в терминале.

### Вариант 2: Использование файлов
```bash
# Перейдите в корень проекта
cd /path/to/gdzmbzrc

# Запустите пример
bash examples/scenario1_basic.sh
```

## 📋 Доступные примеры

### 1️⃣ **scenario1_basic.sh** - Базовое распределение с приоритетами
**Демонстрирует:**
- Работу приоритетов A → B → C
- Частичную отгрузку
- Расчет метрик

**Сценарий:**
- 3 заказа с разными приоритетами (A, B, C)
- Недостаточно товара для всех
- Класс A получает весь запрос, B получает частично, C не получает ничего

---

### 2️⃣ **scenario2_service_mode.sh** - Режим "Сервис" (анти-ноль)
**Демонстрирует:**
- Работу режима Q6=YES (Сервис)
- Предотвращение нулевых распределений
- Логику "сначала по 1 каждому, потом остаток по FIFO"

**Сценарий:**
- 3 заказа одного приоритета
- Дефицит товара
- С Q6=YES все получают минимум 1 единицу

---

### 3️⃣ **scenario3_all_or_nothing.sh** - Режим "Все или ничего"
**Демонстрирует:**
- Работу режима Q3=NO (all-or-nothing)
- Отказ от частичной отгрузки

**Сценарий:**
- 2 заказа одного приоритета
- Первый заказ выполнен полностью
- Второй заказ не выполнен (недостаточно для полной отгрузки)

---

### 4️⃣ **scenario4_with_reserves.sh** - Работа с резервами
**Демонстрирует:**
- Обработку резервов (Q4)
- Расчет available = stock - reserved
- Предупреждение B2 (резерв > остаток)

**Сценарий:**
- Товар с резервом
- Available stock уменьшается на величину резерва
- Возможно предупреждение о превышении

---

### 5️⃣ **scenario5_date_sorting.sh** - Сортировка по дате
**Демонстрирует:**
- Работу режима Q5=YES (сортировка по дате)
- Обработка заказов по срокам, а не FIFO

**Сценарий:**
- 3 заказа одного приоритета с разными датами
- Заказы обрабатываются в порядке дат (раньше → позже)

---

### 6️⃣ **scenario6_stop_error.sh** - Критическая ошибка (STOP)
**Демонстрирует:**
- Работу валидации STOP
- Блокировку выполнения при критических ошибках

**Сценарий:**
- Заказ с некорректным количеством (qty ≤ 0)
- Система останавливается с ошибкой C3

---

### 7️⃣ **scenario7_complex.sh** - Комплексный сценарий
**Демонстрирует:**
- Комбинацию нескольких возможностей
- Несколько SKU
- Разные приоритеты
- Резервы и даты

**Сценарий:**
- Реалистичный сценарий склада
- Несколько товаров
- Разные классы приоритетов
- Резервы

---

## 💡 Интерактивный режим

Для ввода данных вручную используйте:
```bash
python -m src.main --interactive
```

Система запросит ввод Q1-Q6 в интерактивном режиме.

## 📖 Формат входных данных

### Q1: Заказы
```
OrderID|SKU|Qty|Class|DueDate
ORD001|SKU-A|100|A|2026-02-15
ORD002|SKU-B|50|B|-
```

### Q2: Остатки
```
SKU|Qty
SKU-A|500
SKU-B|200
```

### Q3: Частичная отгрузка
- `YES` - разрешена частичная отгрузка
- `NO` - все или ничего

### Q4: Резервы
```
SKU|Reserved
SKU-A|50
```

### Q5: Сортировка по дате
- `YES` - сортировать по дате
- `NO` - FIFO

### Q6: Режим сервис
- `YES` - режим "Сервис" (анти-ноль)
- `NO` - режим "Простота"

## 🎯 Рекомендуемая последовательность

1. Начните со **scenario1_basic.sh** - понимание основ
2. Попробуйте **scenario2_service_mode.sh** - важная функция Q6
3. Изучите **scenario3_all_or_nothing.sh** - режим Q3
4. Проверьте **scenario6_stop_error.sh** - понимание валидации
5. Завершите **scenario7_complex.sh** - полный функционал

## 📊 Ожидаемые результаты

Каждый сценарий выводит:
- ✅ Статус выполнения (SUCCESS/WARN/STOP)
- 📋 Входные данные (Q1-Q6)
- 📊 Результаты распределения
- 📈 Метрики (Fill Rate, Zero Count, Risk Level)

## 🔧 Создание собственных сценариев

Используйте примеры как шаблоны для создания собственных тестовых сценариев:

```bash
python -m src.main \
  --q1 "ВАШ_ЗАКАЗ|SKU|QTY|CLASS|DATE" \
  --q2 "SKU|QTY" \
  --q3 YES \
  --output мой_отчет.md
```
